## Zoom-out findings

Context sufficiency passes. The reviewer checked "existing code" claims against Blue Grid and found no DXF code there.

| ID | Severity | Scope | Finding |
| --- | --- | --- | --- |
| Z1 | Blocker | Goals 1-17; delivery phases; plan | The scope is a rewrite of a roughly 217-file app aiming at about nine products at once. Phase 0 alone creates about 60 files before any engineering exists. The first release (Phase 3) arrives after the full engine, a new editor, two renderers and three document types. No minimum shippable slice is named as the real cut line, and there is no Blue Grid parity checklist. Suggests naming the smallest first release and deferring Goals 7, 14, 15, 17 and Phases 4-6 from committed scope. |
| Z2 | Major | Event log as saved project | The only stated justification is cloud sync, which is a Phase 6 non-goal for release 1. It adds a permanent migration burden per command meaning, and the file would hold two things to migrate (document schema and command semantics). Simpler: a versioned JSON document with an in-memory undo stack, and a log added when sync is built. "Commands are the only write path" already gives the seam. |
| Z3 | Major | Worker, spatial index, mesh solver | The brief said to check Blue Grid's pure helpers before copying, but the design plans fresh code without recording a decision. Blue Grid has a tested coalescing state machine (`simulation/workerProtocol.ts`), `lib/spatialIndex.ts`, `lib/viewport.ts`, `lib/pathfinding.ts`, `simulation/MeshSolver.ts` (reported as a sparse, dependency-free solver; the Elephant has not verified this) and `components/modals/TCCModal.tsx` for Phase 4. State port, adapt or rewrite per file, and map Blue Grid's test numbers to reference cases. |
| Z4 | Major | In-house numeric core | Alternatives S and T are rejected with no technical reason. Dense LU may not be needed in Phase 1 because load flow is iterative. State the dependency-versus-verification trade-off. |
| Z5 | Major | Two renderers plus `scene` | Premature. The only evidence is that Blue Grid needed culling. Suggests SVG with culling first, keeping `scene` as the seam for DXF and PDF, and adding canvas after a measured problem. The UI split into `scene`, `symbols`, `ui`, `editor`, `platform` and `editions` happens before any consumer exists. |
| Z6 | Major | Detailed Implementation Plan | About 150 files with per-file rationale, plus unmeasured values (200-command snapshots, 20 MB compaction). This belongs in per-phase specs, and the design already requires specs for Phases 2-6 but not 0-1. Keep layer, entity and interface sketches and move file lists out. |
| Z7 | Major | Catalog size (40 to 20-24) | The brief says the owner's field-usage list should override the code-only triage. The design does not record that it was obtained. |
| Z8 | Minor/Major | Overview "Decisions made while drafting" | About 20 decisions, several with invented failure modes for features outside version 1 (cloud lock, licence tampering, zero-sequence data, snapshot numbers). Licence tampering appears twice. "Open Questions: none" contradicts pointers at lines 263 and 449. |
| Z9 | Major | Reference tests | Pandapower answers are generated by hand and committed, tolerances are "proposed" yet used as exit gates, and the file-format and provenance process is under-specified for the design's central trust promise. |
| Z10 | Nit | Alternatives | F, G, H and J are drafting defaults without analysis. K to T give no rationale. The section reads as inventory. |
| Z11 | Nit | Layer table | `i18n` is importable from all layers including `model` and `engine`, though the engine returns codes only. The `ui` row ("everything above except platform adapters") is inconsistent. |

Verdict: the root-problem focus, node-based model, per-type solvers and no-silent-defaults rule are sound. The weight is in speculative infrastructure (event log, dual renderers, edition layers, the 150-file plan) and an unrecorded reuse analysis against Blue Grid. The reviewer asks for Z1-Z3 to be fixed before approval.

## Inventive catalyst findings

This reviewer did not read `boq_options.md` or the Blue Grid source. It judged from the design text.

| ID | Severity | Scope | Contradiction and proposed resolution |
| --- | --- | --- | --- |
| IC1 | Major | Balanced solver, CUJ 3, Alternatives K and L | The design accepts "balanced now, per-conductor never" as a limit, yet the model stores per-conductor data, CUJ 3 says the simulation uses it, and Goal 6 needs minimum phase-to-earth faults and earth loops. `phase-allocation.ts` is a second method beside the solver, which is Alternative L under another name. Resolution: one conductor-level nodal assembly with per-type solvers as strategies over it. Balanced positive-sequence becomes a reduction, and "estimate" applies only where a reduction is used. Harder to build first and needs a conditioning story and its own reference cases. |
| IC2 | Major | Per-type solvers, boundaries, short circuit | Boundary iteration with an iteration cap accepts non-convergence as a visible failure. Short circuit crosses transformers by design, so it needs a whole-network model. Resolution: one coupling interface (Norton or Thevenin equivalent per converter), block elimination for linear regions, iteration only for nonlinear converters. |
| IC3 | Major | Event log, topology, cloud | The log is the saved project and the sync unit, but migrations and compaction rewrite it, which an append-only log cannot do. A busbar accept is a multi-step change, and nothing makes it atomic. Resolution: current state canonical and the log a derived journal, a transaction command for atomic groups, log epochs, and migrations that upcast at read time. |
| IC4 | Major | Hybrid rendering, i18n | The stated reason for SVG is browser bidi and focus handling, which canvas, DXF and PDF lack, so `scene` must do its own bidi and text measurement. Resolution: SVG only, with semantic level of detail in `scene` and an offscreen overlay for heavy animation. Measure in Phase 2. |
| IC5 | Major | Goal 2 and Circuit entity vs CUJ 1 | "No silent defaults" conflicts with CUJ 1 creating a default cable on every new wire. A stored circuit that is "suggested then edited" is a second copy of connectivity. Resolution: defaults as an explicit project-level record that wires reference, with trace origin "default"; store circuit overrides only and report stale overrides. |
| IC6 | Major | Layers, `platform`, phases, Goal 17 | `platform` interfaces are promised in Phase 0 but appear only in Phase 6. `scene` imports `views`, which imports `engine`, so drawing depends on calculation. Resolution: types-only `platform` in Phase 0, `scene` depending on result types in `model`, and a worker client stub for `ui`. |
| IC7 | Major | Strict rules vs delivery speed; sign-off gate | About 120 Phase 0-1 files; the owner is the only reviewer of reference cases and Israeli-law cases, which makes the owner the bottleneck. A line cap on solvers can scatter one algorithm. Resolution: treat rules as machine feedback, tiered owner review (only changed or disputed cases), a soft complexity budget instead of a hard line cap. Auto-generated references are only as independent as pandapower. |
| IC8 | Nit | Editions vs one core | Size limits and locks are behaviours in engine and editor paths. Resolution: inject capability policy objects around commands and exporters. |
| IC9 | Nit | Open Questions vs body | "None" conflicts with pointers at lines 263 and 449 and with Phase 6's "conflict rule is decided". A lock contradicts command-level merge. State the lock as the decision. A lock needs lease expiry and cannot work for an offline edition. |
